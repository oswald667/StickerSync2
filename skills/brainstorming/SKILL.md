# Brainstorming — Frameworks de pensée créative structurée

---

## 1. Principe fondamental : Diverger avant de Converger

Toute session de brainstorming suit cette séquence obligatoire :

```
DIVERGER (quantité) → INCUBER → CONVERGER (qualité)
```

**Règle d'or pendant la divergence** : aucun jugement. Une idée "stupide" peut débloquer une idée brillante. La censure précoce tue la créativité.

---

## 2. Techniques de divergence — Générer des idées

### 2.1 Brainstorming classique — Les 3 vitesses

**Vitesse 1 — Évident (2 min)**
Lister toutes les idées qui viennent immédiatement. Ce sont les réponses "par défaut". Ne pas s'arrêter là.

**Vitesse 2 — Associations (3 min)**
Repartir des idées de la vitesse 1, en faire des analogies, les combiner, les inverser.

**Vitesse 3 — Absurde (2 min)**
Pousser délibérément vers l'extrême, l'irréaliste, le provocateur. Souvent la vitesse 3 contient des graines d'idées genuinement nouvelles.

---

### 2.2 SCAMPER — Transformer l'existant

Appliquer chaque lettre à l'idée/produit/problème :

| Lettre | Action | Question |
|--------|--------|----------|
| **S** | Substitute | Que peut-on remplacer ? (composant, processus, personne) |
| **C** | Combine | Que peut-on fusionner avec autre chose ? |
| **A** | Adapt | Qu'est-ce qui existe ailleurs qu'on pourrait adapter ? |
| **M** | Modify / Magnify | Qu'est-ce qu'on peut amplifier, exagérer, réduire ? |
| **P** | Put to other uses | Comment l'utiliser différemment ou pour un autre public ? |
| **E** | Eliminate | Qu'est-ce qu'on peut supprimer sans perdre l'essentiel ? |
| **R** | Reverse / Rearrange | Et si on inversait le processus ? Réordonnait les étapes ? |

---

### 2.3 How Might We (HMW) — Reframer le problème

Transformer un problème en opportunité de design.

**Format** : "Comment pourrions-nous [verbe d'action] [résultat souhaité] pour [utilisateur/contexte] ?"

**Règles** :
- Ni trop large ("HMW améliorer l'expérience ?") → trop vague
- Ni trop étroit ("HMW ajouter un bouton vert ?") → déjà une solution
- Le bon niveau : ouvre des options sans présupposer la solution

**Exemple** :
```
Problème : "Les utilisateurs abandonnent le formulaire d'inscription"

❌ Trop large   : "HMW améliorer l'inscription ?"
❌ Trop étroit  : "HMW réduire le nombre de champs ?"
✅ Juste        : "HMW faire en sorte que l'utilisateur perçoive la valeur
                   avant de s'engager ?"
```

---

### 2.4 Analogies & Transfert de domaine

Prendre une solution d'un domaine étranger et l'appliquer au problème.

**Processus** :
1. Identifier le **mécanisme core** du problème ("comment créer de l'engagement récurrent ?")
2. Chercher des domaines où ce mécanisme est résolu autrement (jeux, nature, finance, médecine…)
3. Abstraire la solution du domaine source ("les jeux utilisent des loops de récompense variable")
4. Transposer dans le contexte cible

---

### 2.5 Inversion — Penser à l'envers

Plutôt que "Comment résoudre X ?", se demander "Comment **garantir** X échoue ?"

Lister toutes les façons de **saboter** l'objectif → inverser chaque sabotage → nouvelles solutions.

**Exemple** :
```
Objectif : "Fidéliser les utilisateurs de l'app"

Inversion : "Comment faire fuir tous les utilisateurs ?"
  → Rendre l'onboarding long et confus
  → Ne jamais envoyer de notifications pertinentes
  → Masquer les fonctionnalités clés
  → Ne pas sauvegarder la progression

Inversé :
  → Onboarding < 3 étapes, valeur immédiate
  → Notifications contextuelles et actionnables
  → Feature discovery progressive
  → Auto-save systématique
```

---

### 2.6 Six Chapeaux de De Bono — Perspectives multiples

Explorer une idée sous 6 angles en changeant délibérément de "chapeau" :

| Chapeau | Couleur | Focus |
|---------|---------|-------|
| Faits | ⚪ Blanc | Données, chiffres, ce qu'on sait et ce qu'on ne sait pas |
| Émotions | 🔴 Rouge | Ressenti, intuitions, réactions gut |
| Critique | ⚫ Noir | Risques, problèmes, pourquoi ça peut échouer |
| Optimisme | 🟡 Jaune | Bénéfices, opportunités, meilleures hypothèses |
| Créativité | 🟢 Vert | Alternatives, idées nouvelles, "et si…" |
| Process | 🔵 Bleu | Organisation, prochaines étapes, vue d'ensemble |

## 3. Techniques de convergence — Filtrer et prioriser

### 3.1 Matrice Impact / Effort

Placer chaque idée dans un quadrant :

```
          IMPACT FORT
               │
    Quick wins │  Big bets
   (faire vite)│  (planifier)
               │
EFFORT ────────┼──────── EFFORT
FAIBLE         │         ÉLEVÉ
               │
  Fill-ins     │  Money pit
  (si le temps)│  (éviter)
               │
          IMPACT FAIBLE
```

**Prioriser** : Quick wins d'abord → Big bets ensuite → Fill-ins si capacité → Money pit : abandonner.

---

### 3.2 Dot voting (pour groupes ou solo)

Attribuer N points (souvent 3–5) par idée, les distribuer librement. Les idées avec le plus de points remontent.

**Variante pondérée** : 1 point = "intéressant", 2 points = "fort potentiel", 3 points = "doit être fait".

---

### 3.3 Critères pondérés — Scoring objectif

Définir 3–5 critères de sélection + poids, noter chaque idée de 1 à 5.

```
Critère          | Poids | Idée A | Idée B | Idée C
Faisabilité      |  30%  |   4    |   2    |   3
Impact utilisateur|  40%  |   3    |   5    |   4
Vitesse (TTM)    |  20%  |   5    |   2    |   3
Différenciation  |  10%  |   2    |   5    |   4
─────────────────────────────────────────────────
Score pondéré    |       |  3.4   |  3.6   |  3.5
```

---

### 3.4 Pre-mortem — Stress-test d'une idée

Imaginer que l'idée a **échoué** dans 12 mois. Lister toutes les raisons de cet échec.

**Bénéfice** : révèle les risques cachés, permet de les mitiger avant de commencer.

```
"Dans 12 mois, le feature X est un échec. Pourquoi ?"
  → Personne ne l'a trouvé (discovery)
  → Les utilisateurs n'ont pas compris la valeur (messaging)
  → La concurrence a copié + amélioré en 3 mois (time-to-market)
  → Le coût de maintenance > valeur générée (complexité)
```

## 4. Frameworks de problème — Cadrer avant d'idéer

### 4.1 Jobs-to-be-Done (JTBD)

Reformuler le besoin sous la forme :
> "Quand [situation], je veux [motivation], pour que [résultat attendu]."

**Exemple** :
```
❌ "Les utilisateurs veulent une app de workout"
✅ "Quand je rentre du travail fatigué, je veux une séance courte et guidée,
    pour que je me sente moins coupable sans effort de décision."
```

Le JTBD révèle les vrais concurrents (ici : le canapé, pas Nike Run Club).

---

### 4.2 SWOT — Analyse rapide

| | Positif | Négatif |
|--|---------|---------|
| **Interne** | Forces | Faiblesses |
| **Externe** | Opportunités | Menaces |

Utiliser le SWOT pour **générer des stratégies** :
- Forces × Opportunités → Stratégies offensives
- Forces × Menaces → Stratégies défensives
- Faiblesses × Opportunités → Amélioration prioritaire
- Faiblesses × Menaces → Plans de contingence

---

### 4.3 Problem Reframing — 5 questions

Avant de brainstormer, vérifier que le bon problème est posé :

1. **Quel est le vrai problème derrière le problème énoncé ?**
2. **Pour qui exactement est-ce un problème ?**
3. **Quand ce problème survient-il ? Dans quel contexte ?**
4. **Quel serait le monde idéal si ce problème n'existait pas ?**
5. **Qu'est-ce qui empêche d'y arriver aujourd'hui ?**

## 5. Structure d'une session de brainstorming

```
Phase 1 — CADRAGE (5 min)
  → Formuler le problème / objectif en une phrase
  → Définir les contraintes (ce qui est non-négociable)
  → Rappeler les règles (pas de jugement en phase divergente)

Phase 2 — WARM-UP (5 min)
  → Exercice d'association rapide pour "dé-bloquer" le cerveau
  → Ex : "10 usages insolites d'un stylo" en 2 min

Phase 3 — DIVERGENCE (15–20 min)
  → Brainstorming vitesse 1, 2, 3 (ou autre technique)
  → Toutes les idées notées, rien écarté

Phase 4 — INCUBATION (pause ou lendemain)
  → Laisser le cerveau inconscient travailler
  → Revenir avec un regard neuf

Phase 5 — CONVERGENCE (15 min)
  → Dot voting ou scoring
  → Sélectionner 3–5 idées à approfondir

Phase 6 — PROCHAINES ÉTAPES (5 min)
  → Pour chaque idée retenue : qui ? quoi ? quand ?
```

---

## 6. Anti-patterns à éviter

| Anti-pattern | Symptôme | Remède |
|-------------|---------|--------|
| HiPPO effect | L'idée du plus haut gradé s'impose | Votes anonymes, facilitation neutre |
| Anchoring | On reste proche de la 1ère idée | Forcer 3 vitesses, phase absurde obligatoire |
| Pensée de groupe | Tout le monde acquiesce | Chapeau noir obligatoire, avocat du diable |
| Brainstorming → réunion | On discute au lieu de générer | Idées d'abord en silence, discussion ensuite |
| Too many ideas | Paralysie par l'excès d'options | Critères de convergence définis avant la session |
